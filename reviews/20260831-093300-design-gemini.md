### 2. Visual Hierarchy — Score: 5/5
* **Hierarchy enforcement:**  
  The system strictly governs visual weight across all surfaces:
  1. **Button hierarchy:** Controlled via four discrete ranks in [`assets/theme.css:286-310`](file:///home/m/dev/pumasi-web/assets/theme.css#L286-L310). A page is limited to exactly one primary action (`.button` with `--accent` fill). Secondary actions use `.button-quiet` (outline only), tertiary uses `.button-ghost`, and destructive actions use `.button-danger` (outlined red, never filled until hover to prevent accidental clicks).
  2. **Stage ladder weight:** The status ladder (`.badge-planned` $\rightarrow$ `.badge-seed` $\rightarrow$ `.badge-alpha` $\rightarrow$ `.badge-beta` $\rightarrow$ `.badge-launched`) in [`assets/theme.css:390-401`](file:///home/m/dev/pumasi-web/assets/theme.css#L390-L401) reserves filled solid green strictly for `[LAUNCHED]`, ensuring visual prominence directly tracks deployment maturity.
  3. **Interaction vs. Signal separation:** The rule that `--signal` (`--signal-sign: #2350c8`, `--signal-booking: #a1442a`, `--signal-tunnel: #0e6f77`) *identifies* but *never colours a control* completely prevents the UI fragmentation seen in multi-product suites where buttons adopt different brand colors across screens.

### 4. Consistency — Score: 5/5
* **Systemic Cohesion:**  
  This is a unified system rather than a website with exceptions. [`/home/m/dev/pumasi-web/assets/brand/product-theme.css`](file:///home/m/dev/pumasi-web/assets/brand/product-theme.css) does not override the shared core tokens; it inherits the entire geometry, spacing, palette, badge system, and button hierarchy from [`theme.css`](file:///home/m/dev/pumasi-web/assets/theme.css).
* **Controlled Domain Licences:**  
  The three licensed product deviations are strictly delimited by clear ergonomic needs:
  1. Setting `--font-body: var(--font-ui)` for high-density tables/forms while retaining `--font-display: var(--font-mono)` for headings and metadata.
  2. Resolving the shared 4-step elevation tokens (`--elev-0` through `--elev-3`) to ink-tuned box-shadows (`rgba(10, 10, 9, 0.05-0.12)`) in application layers for floating menus/modals.
  3. Specifying dedicated primitives ([`.slot`](file:///home/m/dev/pumasi-web/assets/brand/product-theme.css#L184) for Booking, [`.seal`](file:///home/m/dev/pumasi-web/assets/brand/product-theme.css#L197) for Sign, [`.terminal`](file:///home/m/dev/pumasi-web/assets/brand/product-theme.css#L214) for Tunnel) without altering the button or form grammar.

### 5. Asset Craft — Score: 5/5
* **16px Silhouette and Rendering:**  
  As verified in [`/tmp/gate/pumasi-brand-light.png`](file:///tmp/gate/pumasi-brand-light.png) and [`/tmp/gate/pumasi-brand-dark.png`](file:///tmp/gate/pumasi-brand-dark.png), every mark is constructed on a 32×32 grid with 2-unit strokes and zero curves:
  * `pumasi-icon.svg`: 2 brackets enclosing 3 offset horizontal bars; highly distinct at 16px.
  * `pumasi-sign-icon.svg`: Turned-corner page with an internal diamond seal; legible at 16px.
  * `pumasi-booking-icon.svg`: 6-cell calendar grid with 1 highlighted slot and dual top-hangers; eliminates the noise of 30-cell calendars at favicon sizes.
  * `pumasi-tunnel-icon.svg`: 3 input streams multiplexing into a single solid outbound stream.
* **SVG Well-Formedness & Dual Theming:**  
  All 9 SVG files in [`assets/brand/`](file:///home/m/dev/pumasi-web/assets/brand/) parse cleanly with zero XML errors and contain no illegal `--` sequences in XML comments. Every SVG includes an internal `<style>` block using `var(--token, #literal)` paired with `@media (prefers-color-scheme: dark)`, allowing correct rendering both when inlined (inheriting CSS properties) and when embedded in `<img>` tags or favicons across light and dark modes.
* **Logo Lockup:** [`pumasi-logo.svg`](file:///home/m/dev/pumasi-web/assets/brand/pumasi-logo.svg) utilizes `textLength="94"` with `lengthAdjust="spacing"` to lock wordmark geometry uniformly across client environments without distorting letterforms.

### Strongest Argument Against Merging
The strictest constraint in the system is maintaining `--font-display: var(--font-mono)` across application surfaces ([`product-theme.css:94`](file:///home/m/dev/pumasi-web/assets/brand/product-theme.css#L94)) along with universal square corners (`--radius: 0`). While this creates a recognizable brand identity for technical operators and machines, users migrating from incumbent consumer/enterprise SaaS (such as Calendly or DocuSign) may initially perceive uppercase tracked monospace field labels and unrounded form inputs as utilitarian or stark.
